# 「에이지 오브 도미니언(가칭)」 게임 디자인 문서 — 구석기에서 미래까지, 채팅으로 외교하는 멀티플레이 전략 게임

**결론부터:** Godot 4.6 1인 바이브 코딩 프로젝트라면 **"하나의 결정론적 시뮬레이션 코어 + 두 개의 룰셋(빠른 영토 모드 / 대전략 모드)"** 구조가 가장 현실적입니다. 먼저 **OpenFront형 빠른 영토 확장 모드를 MVP로 완성**하고(타일 격자, 4~5개 시대, 채팅+조약, 간단한 유틸리티 AI), 대전략 모드는 같은 코어 위에 "프로빈스 레이어·생산·연구 트리·전선"을 덧붙이는 확장판으로 개발하세요. 네트워크는 **서버 권위형 명령(Intent) 릴레이 + 결정론적 틱 시뮬레이션**(OpenFront와 같은 방식)으로 하고, 언어는 웹 export를 쓸 수 있도록 **GDScript를 기본**으로, 성능이 중요한 부분만 GDExtension이나 컴퓨트 셰이더로 처리하는 것을 추천합니다.

## TL;DR
- **구조:** 공통 코어(맵·시대·자원·외교·채팅·네트워크) 하나에 모드별 룰셋 데이터(JSON/Resource)만 바꿔 끼우는 데이터 주도 설계로 두 모드를 공존시킵니다. 빠른 모드(15~30분, 8개 시대 압축)를 먼저 만들고, 대전략 모드(2~6시간, 저장·재접속 지원)는 2단계로 확장합니다.
- **핵심 차별점:** 실시간 채팅(전체/1:1 비밀/동맹)과 조약 시스템(불가침·동맹·무역·영토 교환·휴전)을 연동하고, "배신자" 낙인과 조약 파기 페널티로 약속에 무게를 줍니다. AI 국가는 유틸리티 AI로 만들고, 선택 기능으로 LLM 외교 대화를 붙입니다(Meta CICERO 등 선례 있음).
- **현실적 범위:** 1인 개발자는 MVP 3~4개월, 알파 6~9개월, 베타 12~18개월을 잡으세요. 가장 흔한 실패 원인은 "처음부터 HOI4급 깊이를 노리는 범위 폭발"과 "나중에 멀티플레이를 붙이려는 설계"입니다. 멀티플레이와 결정론은 1주차부터 넣어야 합니다.

## 1. 게임 개요 / 컨셉

| 항목 | 내용 |
|---|---|
| 장르 | 실시간(일시정지 가능) 멀티플레이 대전략 + 영토 확장 io 게임 |
| 핵심 판타지 | "친구들과 채팅으로 동맹을 맺고 배신하며, 돌도끼 부족에서 우주 문명까지 키운다" |
| 플레이 인원 | 빠른 모드 2~16명(+봇 최대 100), 대전략 모드 2~8명(+AI 국가) |
| 플랫폼 | PC(Windows/Linux/macOS), 웹 브라우저(빠른 모드 우선) |
| 엔진 | Godot 4.6, GDScript 중심 |
| 레퍼런스 | Hearts of Iron IV(깊이), OpenFront.io(속도·접근성), Civilization/Rise of Nations/Empire Earth(시대 전환), Diplomacy/Supremacy 1914(채팅 외교) |

**디자인 필러(설계 원칙) 3가지**
1. **말이 곧 무기다:** 채팅과 조약이 군사력만큼 중요합니다. 약한 플레이어도 외교로 살아남을 수 있어야 합니다.
2. **시대가 판을 뒤집는다:** 시대 전환은 단순한 수치 인플레이션이 아니라 전투 방식과 맵을 읽는 방식 자체를 바꿔야 합니다(예: 항해 시대에 바다가 열리고, 항공 시대에 전선이 무의미해짐).
3. **한 판의 길이를 선택한다:** 점심시간 20분 판도, 주말 저녁 4시간 판도 같은 게임 안에서 즐길 수 있어야 합니다.

## 2. 레퍼런스 게임 분석 — 무엇을 가져오고 무엇을 버릴까

### 2.1 Hearts of Iron IV (Paradox, 2016)
- **맵:** 수천 개 프로빈스를 수백 개 "스테이트(주)"로 묶은 2단 구조입니다. 전투·이동은 프로빈스 단위, 건설·자원·생산은 스테이트 단위입니다. → **가져올 것:** 2단 계층(타일/프로빈스 → 지역). 1인 개발 기준으로는 프로빈스 300~800개 수준이 적절합니다.
- **생산·산업:** 민간 공장/군수 공장 분리, 생산 라인 효율, 자원(강철·석유 등) 무역. → **간소화:** "생산력(PP)" 하나와 시대별 전략 자원 2~3개만 사용합니다.
- **연구:** 연구 슬롯 수 제한, 연도보다 앞선 기술에는 "선행 페널티"를 부과합니다. → **가져올 것:** 선행 페널티와 후발 보너스(격차 완화 장치로 매우 유용).
- **사단·전선:** 사단 템플릿(대대 조합), 전선에 사단을 배정하면 AI가 미시 조작을 대신하고, 공세 화살표를 그립니다. → **가져올 것(대전략 모드):** "전선 그리기 + 자동 배치"는 수백 개 유닛 미시 조작을 없애 주므로 1인 개발에서도 UX 가치가 매우 큽니다.
- **외교·국가 방침:** 진영(Faction), 보장, 전쟁 목표 정당화, 평화 회의, 국가 포커스 트리. → **간소화:** 포커스 트리 대신 "시대별 정책 카드 선택"을 둡니다.
- **멀티플레이:** 호스트 기반 결정론적 락스텝으로 모든 클라이언트가 같은 시뮬레이션을 돌리고, 게임 속도는 가장 느린 PC에 맞춰집니다. 동기화가 어긋나면(OOS) 재동기화하며, 진행 중인 게임에 합류해 AI 국가를 넘겨받는 "핫조인"을 지원합니다. 플레이어 간 외교는 사실상 게임 밖 음성 채팅으로 이루어집니다. → **기회:** HOI4가 비워 둔 "게임 내 채팅 외교"가 바로 우리 게임의 차별점입니다.

### 2.2 OpenFront.io (오픈소스 웹 RTS)
- **맵:** 실제 지도 기반의 대형 픽셀/타일 격자. 영토는 타일 단위로 번지듯 확장됩니다.
- **핵심 루프:** 인구(병력)가 시간이 지나면서 늘어납니다 → 인접 영토에 "병력 비율"을 정해 공격 → 영토가 커지면 인구 상한과 수입 증가 → 금으로 도시·항구·방어 시설·미사일 등을 건설합니다.
- **AI:** 단순 확장형 "Bots"와 실제 국가 위치에 배치되는 똑똑한 "Nations"(건설·공격·동맹·이모지 사용) 두 종류가 있습니다.
- **동맹/배신:** 동맹 요청과 수락, 동맹 간 병력·금 지원이 가능합니다. 동맹을 공격하면 일정 시간 "Traitor(배신자)" 표시와 페널티가 붙습니다. 후기 버전에는 동맹 만료와 갱신이 들어갔습니다.
- **네트워크 구조:** TypeScript 클라이언트/서버가 코어 로직을 공유합니다. 클라이언트는 "Intent(의도: 공격·건설·동맹 요청 등)"를 서버로 보내고, 서버는 틱마다 이를 묶어 "Turn"으로 브로드캐스트합니다. 모든 클라이언트가 같은 결정론적 시뮬레이션을 돌리며 해시로 디싱크를 감지합니다. → **그대로 차용 권장:** 1인 개발자에게 가장 검증된 구조입니다.
- **라이선스:** AGPL-3.0 계열로 알려져 있습니다. **코드를 직접 복사하면 우리 게임 전체 소스를 공개해야 할 수 있으므로**, 구조와 아이디어만 참고하고 코드는 새로 작성하세요(라이선스 파일은 직접 확인 필요).
- **매치 길이:** 보통 10~30분, 영토 약 80% 장악 또는 타이머 종료로 승리합니다.

### 2.3 시대 발전 레퍼런스

## 3. 두 모드 상세 설계

### 3.1 공존 원칙: "코어 공유, 룰셋 분리"
```
SimCore (공통, 결정론)
 ├─ MapGrid (타일)  ── RegionLayer (프로빈스/지역: 대전략 모드만 활성)
 ├─ EraSystem       ── era_ruleset_blitz.json / era_ruleset_grand.json
 ├─ Economy         ── 단순(금·인구) / 확장(생산력·전략자원·무역)
 ├─ Combat          ── 타일 침투 전투 / 프로빈스 전투+전선
 ├─ Diplomacy       ── 조약 종류와 기간만 룰셋별로 다름
 └─ Chat            ── 완전 공통
```

| 항목 | ⚡ 빠른 영토 모드 "Blitz" | 🏛 대전략 모드 "Dominion" |
|---|---|---|
| 세션 | 15~30분 | 2~6시간(여러 세션으로 나눠 진행 가능) |
| 인원 | 2~16명 + 봇 | 2~8명 + AI 국가 6~20 |
| 맵 | 타일 격자 1000×500~2000×1000 | 타일 격자 + 프로빈스 300~800 |
| 시대 진행 | 8시대를 약 3분마다 자동/연구로 압축 진행 | 기술 연구 누적, 한 시대 20~40분 |
| 조작 | 공격 비율 슬라이더 + 클릭, 건물 5~8종 | 사단 템플릿, 전선, 생산 라인, 정책 카드 |
| 승리 | 영토 70~80%, 시간 종료 시 점수 | 점수/지배/우주 이주 프로젝트(과학 승리)/동맹 공동 승리 |
| 저장·재접속 | 재접속만(서버 메모리) | 서버 저장 + 핫조인 + 이탈 시 AI 대행 |
| 일시정지 | 없음 | 투표 일시정지, 속도 1~5단계 |

### 3.2 Blitz 모드 핵심 루프
1. 스폰 위치 선택(10초) → 2. 인구가 자동 증가(현재 인구/상한 비율에 따라 로지스틱 성장) → 3. 빈 땅이나 적 땅에 병력 % 투입 → 4. 금으로 건물 건설 → 5. 시대 게이지가 차면 시대 전환(선택형 보너스 3택 1) → 6. 채팅·조약으로 동맹과 배신.
- **시대 게이지:** 시간 + 영토 크기 + "연구소" 건물로 채웁니다. 최하위 플레이어는 게이지 획득량 +30%(후발 보너스)를 받습니다.

### 3.3 Dominion 모드 핵심 루프
1. 국가 선택(무작위 생성 대륙 또는 프리셋) → 2. 지역별 건물(농장·광산·공방·공장·연구소) 배치 → 3. 연구 슬롯 3~5개로 기술 연구 → 4. 유닛 템플릿 설계 후 생산 → 5. 전선 배정·공세 화살표 → 6. 외교·조약·평화 회의 → 7. 시대 전환 이벤트(정책 카드 재선택, 정부 형태 변화).
- **세션 분할:** "주말 캠페인" 방식입니다. 호스트/서버가 매 게임일마다 자동 저장하고, 다음 모임에서 이어서 합니다. 빠진 친구의 국가는 AI가 "보수적 성향"으로 대행합니다.

## 4. 시대 발전 시스템

### 4.1 8시대 구성
| # | 시대 | 대표 유닛 | 핵심 자원 | 전투 방식 변화 | 열리는 규칙 |
|---|---|---|---|---|---|
| 1 | 구석기 | 수렵 무리, 투석병 | 식량 | 인구 = 병력, 이동 느림 | 채집 영토, 불(야간 방어) |
| 2 | 신석기 | 창병, 목책 | 식량, 목재 | 정착지 방어 보너스 | 농업(인구 상한↑), 영구 정착 |
| 3 | 고대 | 청동 보병, 전차, 궁병 | 구리/주석, 금 | 병종 상성(가위바위보) | 도시, 도로, 최초 조약(조공) |
| 4 | 중세 | 기사, 석궁병, 공성기 | 철, 말 | 성채 공성전 | 성, 봉신 관계, 해안 항해 |
| 5 | 근세 | 머스킷, 대포, 범선 | 화약, 교역품 | 원거리 화력 중심, 해양 진출 | 대양 항해, 식민, 무역 조약 |
| 6 | 산업 | 소총 보병, 철갑선, 철도 | 석탄, 강철 | 참호전·보급선, 전선 시스템 본격화 | 철도(빠른 이동), 공장 |
| 7 | 현대 | 전차, 항공기, 핵무기 | 석유, 우라늄 | 기동전·공중 우세·전략 폭격 | 항공 영역, 핵 억지(사용 시 전 세계 외교 페널티) |
| 8 | 미래 | 드론 군집, 궤도 병기, 사이버전 | 에너지, 희토류 | 원거리 즉시 타격, 해킹(적 건물 무력화) | 궤도 레이어, 과학 승리(항성 이주) |

### 4.2 시대 격차 밸런스 장치
시대 차이가 2단계 이상이면 사실상 게임이 끝나 버리므로, 다음 장치를 **중첩**해서 사용합니다.
1. **기술 확산(Tech Diffusion):** 이미 다른 국가 N곳이 보유한 기술은 연구 비용이 1국당 −10%(최대 −50%)입니다. Civilization의 "다른 문명이 알고 있는 기술 할인"과 같은 개념입니다.
2. **선행 페널티:** 시대 평균보다 앞선 연구는 비용 +50%(HOI4의 연도 페널티 차용).
3. **전투력 격차 상한:** 시대 차이 1당 전투력 +25%, 최대 +60%로 제한합니다. 창병이 전차를 이길 수는 없지만, 수와 지형(산악·요새)으로 버틸 수는 있게 합니다.
4. **방어자 보너스:** 수도·요새 타일에서 방어력 ×1.5. 후진국은 "땅을 지키기" 쉽고 "빼앗기"는 어렵습니다.
5. **동맹 기술 공유 조약:** 외교로 격차를 줄이는 경로를 줘서, 채팅 외교의 가치를 높입니다.
6. **Blitz 전용:** 시대 전환은 개인별이지만 "세계 시대"보다 2단계 이상 뒤처지면 자동 캐치업(게이지 +50%).

## 5. 경제·자원·연구

### 5.1 자원 모델(단순함 우선)
- **공통:** 인구(=병력 풀), 금(범용 화폐).
- **Dominion 추가:** 생산력(PP), 연구력(RP), 시대별 전략 자원 2개(표 4.1의 핵심 자원). 전략 자원이 없으면 해당 유닛 생산 속도 −50%입니다(0으로 막지 않음 → 교착 방지).
- **인구 성장식(두 모드 공통):** `Δpop = r × pop × (1 − pop/cap)`, cap = 영토 타일 수 × 시대 계수 + 건물 보너스. OpenFront처럼 "인구를 병력으로 쓰면 성장률도 줄어드는" 긴장감을 만듭니다.

### 5.2 연구
- Blitz: 시대당 "선택형 특성 3택 1"만 있습니다(연구 트리 없음).
- Dominion: 시대당 기술 8~12개, 총 80~100개. 5개 분야(군사·경제·사회·항해/항공·과학)로 나누고, 연구 슬롯 3개에서 시작해 최대 5개까지 늘립니다. 시대 전환 조건은 "해당 시대 기술 60% 연구 + 시대 전환 프로젝트 완료"입니다.

## 6. 전투 시스템(PvP / PvE / 협동)

### 6.1 Blitz 전투: 타일 침투
- 공격 시 병력 P를 투입하면 경계 타일부터 BFS로 확장합니다. 타일당 소모 병력 = 기본 비용 × 지형 계수 × (방어자 밀도) ÷ (시대 전투력 비율).
- 해상은 항구에서 "상륙선"을 보내고, 현대 이후에는 미사일·핵을 사용합니다(OpenFront식).

### 6.2 Dominion 전투: 프로빈스 + 전선
- 유닛(사단)은 프로빈스에 주둔합니다. 전투는 매 시간 틱마다 공격력/방어력/조직력(사기)을 계산하고, 조직력이 0이 되면 후퇴합니다.
- **전선 도구:** 플레이어가 국경선을 따라 전선을 그리고 사단을 배정하면 AI가 균등 배치합니다. 공세 화살표를 그리면 자동 공격합니다. **1인 개발자에게 가장 비용 대비 효과가 좋은 기능**입니다. 유닛 미시 조작 UI를 만들 필요가 크게 줄어듭니다.
- 보급: 수도/보급 거점에서 거리가 멀수록 전투력이 감소합니다(산업 시대부터 철도로 완화).

### 6.3 모드 구성
| 구성 | 설명 |
|---|---|
| PvP 자유 대전(FFA) | 전원 적대, 외교로 임시 동맹 |
| 팀전(2v2, 4v4) | 팀 채팅, 영토·승리 공유 |
| 협동 PvE | 친구 전원 vs AI 연합("야만인 물결", "AI 제국 연합" 시나리오) |
| 혼합 | 플레이어 + AI 국가 다수, 가장 HOI4다운 구성 |
| 솔로 연습 | 로컬 서버 + AI, 튜토리얼 겸용 |

## 7. AI 설계

### 7.1 기법 비교와 추천
| 기법 | 장점 | 단점 | 추천 용도 |
|---|---|---|---|
| 유한 상태 기계(FSM) | 구현 최단 | 복잡해지면 스파게티 | Blitz 단순 봇 |
| 행동 트리(BT) | 시각화·디버그 쉬움 | 전략 수준의 "무엇이 가장 중요한가" 판단은 어려움 | 유닛/전선 전술 |
| **유틸리티 AI** | 수십 가지 선택지를 점수로 비교, 성향(공격적/외교적) 조정 쉬움, 데이터 주도와 궁합이 좋음 | 점수 곡선 튜닝 필요 | **국가 전략·외교(핵심 추천)** |
| GOAP | 목표→계획 자동 생성 | 구현·디버그 부담이 큼, 전략 게임에서는 과함 | 비추천(1인) |
| MCTS/강화학습 | 강함 | 결정론 네트워크·성능·개발 부담 | 비추천 |

**추천 아키텍처(3계층):**
1. **전략층(유틸리티 AI, 5~10초마다):** "확장/공격/방어/건설/연구/외교" 각 행동에 점수를 매기고 최고점 행동을 실행합니다. 점수 = Σ(고려 요소 × 가중치 곡선). 성향 프로필(JSON)로 "정복자/상인/겁쟁이/기회주의자"를 만듭니다.
2. **작전층(규칙 기반):** 목표 적 선정 → 전선 배정 → 병력 비율 결정.
3. **외교층(유틸리티 + 신뢰도 메모리):** 국가마다 `trust[player]` 값을 유지합니다. 조약 준수는 +, 배신은 큰 −, 그리고 서서히 망각합니다.

**중요:** AI는 **SimCore 안에서 결정론적으로** 돌아야 합니다(시드 기반 난수만 사용). 또는 서버에서만 AI를 돌리고 그 결과를 Intent로 주입해도 됩니다(추천: 서버 실행 → Intent 주입. 클라이언트 부담이 없고 디싱크 위험도 줄어듭니다).

### 7.2 AI 난이도
난이도는 "치팅"이 아니라 **판단 주기·실수 확률·정보 범위**로 조절합니다. 쉬움은 판단 주기 15초에 20% 확률로 차선책을 고르고, 어려움은 판단 주기 3초에 최선책만 고르며 +10% 자원 보너스를 받습니다.

## 8. 채팅 기반 외교 시스템 (핵심 차별화)

### 8.1 채널 구조
| 채널 | 참여자 | 비고 |
|---|---|---|
| 전체(Global) | 전원 | 선전포고·공개 성명, 스팸 방지 쿨다운 3초 |
| 1:1 비밀(DM) | 두 국가 | **다른 플레이어에게는 "A와 B가 대화 중" 사실조차 비공개**(옵션: "첩보" 기술로 대화 여부 탐지) |
| 동맹/진영 | 조약 참여국 | 동맹 결성 시 자동 생성, 파기 시 자동 퇴장 |
| 팀 | 팀전 팀원 | 팀전 전용 |
| 관전/사망자 | 탈락자·관전자 | 생존자에게 정보 유출 방지 |
| 시스템 | — | 조약 체결·파기·배신 공지 |

### 8.2 채팅 ↔ 외교 행동 연동
- **인라인 조약 카드:** 채팅창에서 `/제안` 또는 [조약] 버튼 → 조약 카드가 메시지로 전송 → 상대가 [수락][거절][수정 제안]을 누르면 즉시 게임 상태에 반영됩니다.
- **조약 종류와 효과**

| 조약 | 효과 | 기본 기간 | 파기 조건/페널티 |
|---|---|---|---|
| 불가침 | 상호 공격 불가 | Blitz 5분 / Dominion 10게임년 | 일방 파기 시 30초(Dominion은 1게임월) 유예 후 해제 |
| 동맹 | 공격 불가, 시야·병력·자원 지원, 동맹 채팅 | 만료 후 갱신 투표 | 동맹 공격 시 즉시 "배신자" |
| 무역 | 매 틱 자원 교환(A 금 10 ↔ B 철 5) | 무기한 | 전쟁 시 자동 해제 |
| 영토 교환/양도 | 지정 지역 소유권 이전 | 즉시 | — |
| 휴전 | 전쟁 즉시 중지, 점령지 현상 유지 | 3분 / 5게임년 | 파기 시 배신자 |
| 조공/속국 | 수입 % 이전, 보호 의무 | 무기한 | — |
| 기술 공유 | 상호 연구 비용 −20% | 무기한 | — |

- **지도 연동:** 채팅에서 `@지역명` 또는 지도에서 Alt+클릭하면 해당 위치 핑이 메시지에 첨부됩니다("여기를 같이 치자"). 이 기능이 텍스트 외교의 효용을 크게 높입니다.

### 8.3 배신 메커니즘
- 조약 기간 중 공격 → **"배신자" 낙인**(국가 이름 옆 아이콘, Blitz 60초/Dominion 2게임년): 방어력 −20%, 모든 AI 국가 신뢰도 대폭 하락, 새 조약 제안 쿨다운.
- **배신 자체는 금지하지 않습니다.** Diplomacy 보드게임의 재미는 "배신이 가능하기 때문에 약속이 의미를 가진다"는 데 있습니다. 대신 비용을 명확하게 만듭니다.
- **평판 점수(Dominion):** 게임 내내 누적되는 공개 수치로, 조약을 지키면 오르고 배신하면 떨어집니다. 다른 플레이어가 조약 카드에서 상대의 평판을 볼 수 있습니다.

### 8.4 AI 국가와의 외교
- **기본(필수):** 정형 외교입니다. 조약 카드를 AI에게 보내면 유틸리티 점수(`힘의 비율 + 공동의 적 + 신뢰도 + 성향`)로 수락/거절합니다. 응답 문구는 성향별 템플릿 50~100개로 준비합니다("우리 부족은 약자와 손잡지 않는다").
- **선택(실험 기능): LLM 외교 대화.** 플레이어가 AI에게 자유 텍스트를 보내면 → 서버가 LLM에 [국가 상태 요약 + 성향 + 신뢰도 + 허용 행동 목록]을 넘기고 → LLM은 **자연어 응답 + 구조화된 행동 JSON(`{"action":"propose_treaty","type":"non_aggression"}`)**을 돌려줍니다 → 서버는 그 행동을 **유틸리티 AI가 허용하는 범위 안에서만** 실행합니다(LLM이 게임 규칙을 무시하지 못하게 함).
  - **선례:** Meta의 CICERO(2022년 Science 논문)는 언어 모델과 전략 계획 모듈을 결합해 webDiplomacy.net에서 인간 수준의 성적을 냈습니다. 2025년에는 여러 최신 LLM이 서로 Diplomacy를 두는 "AI Diplomacy" 실험이 공개되기도 했습니다. 핵심 교훈은 **"전략은 기존 AI가 정하고, LLM은 말만 한다"** 구조가 안정적이라는 점입니다.
  - **주의:** API 비용·지연(1~5초)·결정론 문제가 있으므로 LLM 결과는 서버에서 Intent로 변환한 뒤 틱에 주입합니다. 옵션으로 제공하고 사용자 본인의 API 키 입력 방식을 권장합니다.

### 8.5 안전: 욕설 필터·신고
- 클라이언트·서버 양쪽에 금칙어 필터를 둡니다(한국어 자모 분리·변형 대응 목록은 오픈 데이터 활용, 설정에서 끄고 켜기 가능).
- 음소거(개인), 신고(최근 50개 메시지 로그 첨부), 방장 강퇴, 메시지 속도 제한(5초에 3개).
- 친구끼리 하는 비공개 방은 필터 기본 OFF, 공개 매치는 ON.

## 9. 멀티플레이 네트워크 구조

### 9.1 모델 선택: "서버 릴레이형 결정론적 락스텝"
| 모델 | 대역폭 | 치팅 방지 | 구현 난이도 | 대규모 맵 적합성 |
|---|---|---|---|---|
| 상태 동기화(MultiplayerSynchronizer) | 매우 큼(타일 수백만 개 불가) | 좋음 | 쉬움 | ❌ |
| P2P 락스텝 | 작음 | 약함 | 중간 | ⭕ |
| **서버 릴레이 락스텝(추천)** | 작음 | 중간(서버가 명령 검증) | 중간 | ⭕ |
| 서버 권위 + 델타 동기화 | 중간 | 강함 | 어려움 | △ |

- 수백만 타일의 소유권을 매 틱 동기화하는 것은 불가능하므로, **명령(Intent)만 보내고 모든 클라이언트가 같은 시뮬레이션을 돌리는** 방식이 사실상 유일한 해법입니다. HOI4(락스텝)와 OpenFront(Intent 릴레이)가 모두 이 계열입니다.
- **틱:** Blitz 10틱/초(100ms), Dominion은 게임 속도 1~5에 따라 1게임시간 = 1틱.
- **흐름:** 클라이언트 → `Intent{player, tick, type, args}` → 서버가 검증(소유권·자원·쿨다운) → 틱 N의 Intent 묶음 `Turn{N, intents[]}` 브로드캐스트 → 모든 클라이언트가 틱 N 실행 → 10틱마다 상태 해시를 서버로 보내 디싱크를 검사하고, 불일치 시 스냅샷을 재전송합니다.
- **채팅은 시뮬레이션과 분리:** 채팅은 별도 신뢰 채널(RPC)로 즉시 전달합니다. 조약 수락만 Intent로 변환해 틱에 넣습니다.

### 9.2 결정론 체크리스트(가장 중요)
- 시뮬레이션에는 **float 사용 금지 → 정수/고정소수점**(예: ×1000 정수). GDScript float는 64비트라 같은 빌드에서는 대체로 같지만, 플랫폼·빌드 간 차이 위험을 없애려면 정수가 안전합니다.
- 난수는 `RandomNumberGenerator`에 공유 시드를 주고 시뮬레이션 전용 인스턴스만 사용합니다.
- Dictionary 순회 순서에 의존하지 말고, 정렬된 ID 배열로 순회합니다.
- `_process`/`_physics_process`에서 시뮬레이션을 돌리지 말고, 고정 틱 루프에서만 실행합니다.
- 시뮬레이션 코드는 Node가 아닌 **순수 데이터 클래스(RefCounted)**로 작성합니다. 렌더링은 상태를 읽기만 합니다.

### 9.3 서버·접속 방식
| 단계 | 방식 | 이유 |
|---|---|---|
| MVP | **리슨 서버(호스트가 서버 겸 플레이어)**, ENet 직접 IP 또는 Steam 로비 | 서버 비용 0, 친구끼리 즉시 테스트 |
| 알파 | **헤드리스 전용 서버**(같은 Godot 프로젝트를 `--headless`로 실행), 저가 VPS | 호스트 이탈 문제 해결, Dominion 저장·재접속 |
| 베타 | 로비/매치메이킹 서버 + 다수 게임 서버, 웹은 WebSocket | 공개 매치 |

- **전송 계층:** 데스크톱 = ENetMultiplayerPeer(UDP), 웹 = WebSocketMultiplayerPeer(브라우저는 UDP 불가), P2P 웹 = WebRTCMultiplayerPeer(시그널링 서버 필요). 전용 서버가 ENet과 WebSocket을 **동시에** 열면 데스크톱과 웹 크로스플레이가 가능합니다.
- **친구 초대:** Steam 출시 시 GodotSteam(Steam 로비·초대·Steam Networking 릴레이로 NAT 문제 해결). 웹/비Steam은 "6자리 방 코드" + 로비 서버. NAT 때문에 리슨 서버 직접 접속은 실패가 잦으니 초기부터 Steam 릴레이나 전용 서버를 전제로 하세요.
- **재접속/핫조인:** 서버가 최신 스냅샷 + 이후 Turn 로그를 전송해 따라잡게 합니다. 이탈한 플레이어의 국가는 AI 대행(HOI4의 핫조인 개념).

## 10. Godot 4.6 기술 스택 및 아키텍처

### 10.1 Godot 4.6 관련 사항
- Godot 4.6은 2026년 1월 공개된 4.x 마이너 업데이트로, 새 프로젝트의 3D 물리 기본값이 Jolt로 바뀌고 에디터 테마·도킹 개선, 3D IK 프레임워크 복귀, 렌더링(SSR 등) 개선 등이 포함된 것으로 알려져 있습니다. **2D 전략 게임에 직접 영향을 주는 큰 변화는 적으며**, 고수준 멀티플레이 API(MultiplayerAPI/Spawner/Synchronizer, ENet/WebSocket/WebRTC)는 4.0 이후 구조가 거의 그대로입니다. 세부 변경사항은 공식 릴리스 노트에서 직접 확인하세요.
- **TileMap 노드는 4.3부터 사용 중단(deprecated)되었으므로 TileMapLayer를 씁니다.** 단, 이 게임의 대형 맵에는 TileMapLayer보다 아래의 셰이더 방식이 더 적합합니다.
- 웹 export는 4.3부터 단일 스레드 빌드를 지원해 SharedArrayBuffer/COOP·COEP 헤더 없이도 itch.io 등에 올리기 쉬워졌습니다.

### 10.2 GDScript vs C#
| 기준 | GDScript | C# |
|---|---|---|
| 웹 export | ✅ 가능 | ❌ Godot 4.x에서 C# 프로젝트는 웹 export 미지원(4.6 기준에서도 정식 지원 전으로 파악됨) |
| AI 코딩 도구 친화성 | 좋음(단, 3.x 문법 혼동 주의) | 매우 좋음(학습 데이터 풍부) |
| 성능 | 느림(시뮬레이션 핫루프에 부담) | 빠름 |
| 반복 속도 | 즉시 | 빌드 필요 |

**결정:** 웹 Blitz 모드를 원한다면 **GDScript + 타입 힌트 필수**를 사용하고, 병목(타일 확장 BFS, 경로 탐색)은 ① `PackedInt32Array` 기반 알고리즘으로 최적화하고 ② 그래도 부족하면 GDExtension(C++/Rust, 웹도 지원 가능)으로 옮깁니다. 웹을 포기하고 PC 전용이면 C#도 좋은 선택입니다.

### 10.3 대형 맵 렌더링
- **소유권 텍스처 방식(추천):** 타일 격자 W×H를 `Image`(FORMAT_R16 또는 RG8)에 소유자 ID로 기록 → `ImageTexture`로 GPU 업로드 → 셰이더가 팔레트 텍스처에서 색상을 찾고, 인접 픽셀 비교로 국경선을 그립니다. 변경된 영역만 `update()`로 갱신합니다(더티 사각형). 2000×1000 = 200만 타일도 드로우콜 1회로 처리됩니다.
- **지형:** 정적 지형 텍스처 1장 + 소유권 오버레이 셰이더 합성.
- **프로빈스(Dominion):** "프로빈스 ID 맵" 텍스처(색상 = ID) → 마우스 픽킹은 CPU 측 배열 조회, 하이라이트는 셰이더 uniform. Paradox 게임들이 쓰는 방식과 같은 원리입니다.
- **유닛:** 사단 아이콘은 `MultiMeshInstance2D` 또는 줌 레벨에 따라 집계 표시.
- **컴퓨트 셰이더:** RenderingDevice 컴퓨트는 Forward+/Mobile 렌더러 전용이며 웹(Compatibility)에서는 불가능합니다. 또한 결정론 시뮬레이션을 GPU에서 돌리면 안 됩니다. 쓰더라도 **시각 효과(국경 거리장, 안개)용**으로만 쓰세요.

### 10.4 프로젝트 구조
```
res://
├─ core/            # 순수 시뮬레이션(Node 의존 금지, 결정론)
│  ├─ sim_state.gd, sim_tick.gd, intents/, systems/(economy, combat, era, diplomacy)
│  └─ ai/ (utility_ai.gd, profiles/)
├─ data/            # 데이터 주도 정의
│  ├─ eras/*.tres or eras.json, units/, techs/, buildings/, treaties/
│  └─ rulesets/blitz.json, grand.json
├─ net/             # server.gd, client.gd, lobby.gd, chat_service.gd, transport/
├─ presentation/    # 맵 렌더러, 셰이더, UI(채팅, 조약 카드, HUD)
├─ tests/           # GUT/gdUnit4 결정론·규칙 테스트
└─ tools/           # 맵 변환기(PNG→타일 데이터), 밸런스 시뮬레이터
```

## 12. 바이브 코딩 개발 가이드

1. **`CLAUDE.md` / `.cursorrules`에 규칙을 고정하세요:** "Godot 4.6, GDScript 2.0 문법만 사용(`yield` 금지·`await` 사용, `TileMap` 금지·`TileMapLayer`, `export` 대신 `@export`), core/는 Node 상속 금지, 시뮬레이션은 정수만 사용, 모든 함수에 타입 힌트." AI 도구는 Godot 3.x 문법을 자주 섞어 쓰므로 이 규칙이 가장 큰 효과를 냅니다.
2. **작업 단위를 작게:** 한 번에 "시스템 하나 + 테스트". 예: "economy_system.gd에 로지스틱 인구 성장 구현하고 gdUnit4 테스트 3개 작성".
3. **테스트가 AI의 안전망:** 결정론 테스트(같은 시드와 같은 Intent 로그 → 1000틱 후 같은 해시)를 1주차에 만들고, AI가 코드를 고칠 때마다 실행합니다. 이것이 없으면 멀티플레이 디싱크 버그가 쌓입니다.
4. **헤드리스 시뮬레이션 CLI:** `godot --headless -s tools/sim_runner.gd --seed 42 --ticks 5000`으로 AI끼리 대전시켜 밸런스를 확인합니다. AI 도구가 결과 로그를 읽고 스스로 튜닝 제안을 할 수 있습니다.
5. **씬(.tscn)은 사람이, 로직은 AI가:** AI 도구는 .tscn 편집에 약하므로 UI 배치는 에디터에서 직접 하고, 스크립트에서 노드를 `%UniqueName`으로 참조하게 합니다.
6. **데이터 주도:** 새 유닛·시대·기술 추가가 "JSON 한 줄 추가"로 끝나게 만들면, AI에게 "중세 유닛 8종 밸런스 있게 생성" 같은 콘텐츠 작업을 맡길 수 있습니다.
7. **Git 커밋을 자주:** AI가 대규모 수정을 하기 전에 반드시 커밋합니다. 망가지면 즉시 되돌립니다.
8. **아키텍처 문서 유지:** `docs/architecture.md`에 시스템 간 의존 관계를 적어 두고 매 세션 AI에게 참조시킵니다.

## 15. 주의사항(Caveats)
- 이 기획서의 Godot 4.6 세부 변경사항, OpenFront.io의 틱 간격·라이선스 세부, HOI4의 정확한 프로빈스/스테이트 수는 버전에 따라 달라지므로 **개발 시작 전 공식 릴리스 노트와 저장소 LICENSE를 직접 확인**하세요.
- 기간 추정치는 주 20~30시간을 투입하는 1인 개발자 기준의 경험적 추정이며, 바이브 코딩으로 코드 작성은 빨라지더라도 **밸런스·플레이테스트·디버깅 시간은 줄지 않는다**는 점을 감안해야 합니다.
- 수치(전투력 +25%, 배신자 −20% 등)는 출발점 제안값일 뿐이며, 헤드리스 AI 대전과 친구 플레이테스트로 반드시 조정해야 합니다.
- **검증 한계:** 이번 작업 환경에서는 웹 검색과 페이지 조회를 쓸 수 없었습니다. 그래서 이 문서의 사실 정보(Godot 4.6 출시 시기와 기능, OpenFront.io의 구조·라이선스·승리 조건, HOI4 멀티플레이 방식, CICERO와 "AI Diplomacy" 사례, Empire Earth 에포크 수, C# 웹 export 미지원 여부)는 모두 실시간 출처로 확인하지 않은 배경 지식에 기반합니다. 설계를 확정하기 전에 공식 문서로 반드시 교차 확인하세요.
